**중앙값(13편)**: 그림 15개(평가 8, 측정 동기 그림 3), 표 1–2개(정확도 보고 논문은 2–4), 평가 절 4쪽(본문의 25–35 %), baseline 4–5개(엔진 통합 논문은 버전 명시 + 저자가 강화한 baseline + 자체 변형 ablation), 모델 3개, 단일 노드, 실제 데이터셋/트레이스 2–4개 + **짧은 입력 무회귀 대조(ShareGPT)가 거의 전부에 있음**, Poisson 또는 트레이스 재생 + 요청률 스윕(mean+P99). 정확도는 13편 중 4편만 명시 표(SPEX·Kairox·MoE) 또는 Pareto(Murakkab), 나머지는 "구조상 lossless" 한 문장. SLO attainment/goodput 또는 SLO tier는 3편(Prism·PP·Murakkab), 임계선만 그린 것 1편(MoE); $/에너지는 3편(Murakkab $·MWh, Sereno tokens/J, Prism GPU당 매출). Discussion/한계 절은 6편. Artifact Available 배지·artifact appendix 5편(ECHO·SPEX·Kairox·LMetric·Prism).

**평가 절의 표준 골격**: Setup(볼드 run-in 제목: Testbed / Models / Workloads / Baselines / Metrics, 표 아님) → End-to-end(요청률 또는 길이 축의 throughput·TTFT·attainment) → 메커니즘·breakdown → 누적 ablation(+A → +A+B → +A+B+C 막대) → 민감도·일반화(다른 GPU·모델) → 오버헤드 소절 → (실제 트레이스/프로덕션) → Discussion. 질문 제목 소절("How does X perform under …?")은 Strata·Sereno 방식.

**우리가 베낄 발표 장치**: (1) 정확도 표를 end-to-end 그림 바로 옆에, 기준/우리 짝 행 + Avg + 잡음 바닥(seed)과 함께; (2) 예측기(라우터) 품질 → 정확도 → 비용의 인과 사슬 그림(Kairox: recall/precision → 정확도 표); (3) 막대 위 speedup 배수와 effective batch 라벨; (4) 메모리 압박 사다리(48 → 24 GB)와 OOM 표시; (5) throughput–TTFT frontier 격자(데이터셋 × 모델); (6) attainment vs 요청률/SLO scale/GPU 수 + 99 % 도달 GPU 수 = 비용; (7) 누적 기여 막대; (8) oracle 상한; (9) 단계별 waterfall breakdown; (10) 짧은 입력 대조와 오버헤드 소절에서 "어디서 손해 보는지"를 숫자로; (11) $와 에너지 병기; (12) Discussion에서 범위·한계 명시.

## 2. 우리 논문의 OSDI 형태

### 2.1 기여를 시스템 문장으로

MLSys판의 주장 "CD-level accuracy at constant cost with certifiable routing"을 OSDI에서는 **"길이에 무관한 고정 예산의 안전 검사 = 서빙 시스템 속성"**으로 끌고 간다.

1. **메커니즘**: 블록-국소 트렁크 + 라우터 + top-k 창 head = 가드 작업량 O(k)·메모리 O(k)(L 무관). 측정: 128k에서 dense 8B 가드 50 s/45 GB vs LG 1.1 s(0.6B)·14 s(8B)/1.3–16 GB, 1k→128k peak +1.5–8.6 %(S7, G2 (c) PASS). 창 스트리밍(c16)·head 배치(h8)가 그 메모리 평탄성을 만든다(설계 절의 "메커니즘" 그림).
2. **서빙 시스템(GuardServe, S11')**: 가드가 타깃 LLM의 prefill과 겹쳐 돌아 TTFT 오버헤드를 숨기고(overlap), 창이 도착하는 대로 판정하는 스트리밍 조기 종료(time-to-verdict가 needle 위치에만 의존), 요청 간 창 배칭(continuous window batching), 타깃 모델과 같은 GPU 공존(메모리 평탄). **평가 질문 Q3–Q5가 여기서 나옴.**
3. **품질 보존**: 근사(top-k 라우팅 + max/rg3 집계)가 dense·CD 대비 recall을 유지함을 Table 2(짝 행 + 3 seed 잡음 바닥)로; 남는 격차의 원인을 분해(문서 끝 결손 → tail-pad, 팽창 → rg3, 라우팅 미스 4 %)해 "왜 보존되는가"를 설명(Kairox의 recall-우선 예측기 서사).
4. **보안 시스템 속성**: 길이로 가드를 굶기는 sponge/flood(128k 다중 tenant)에서 tail latency가 평평(E5-3), ranking-level 인증(E8).

### 2.2 평가 질문 (논문 §Eval 첫 문단에 그대로)

- **Q1 품질**: 1k–128k에서 LG는 dense·CD·sliding 대비 matched-FPR recall·FPR을 유지하는가(Table 2, Fig 8; 3 seed ±sd).
- **Q2 단일 문서 비용**: 지연·메모리·처리량이 L에 무관한가; 다른 GPU(48/40/24 GB)와 백본(0.6B–8B)에서도 그런가(Fig 2 동기·Fig 12·Fig 15).
- **Q3 서빙 end-to-end**: 부하(Poisson λ)·길이 혼합 아래 가드가 있는 타깃 LLM의 TTFT P50/P99·SLO attainment·goodput이 가드 없음에 얼마나 가깝고, dense 가드·CD 파이프라인보다 얼마나 나은가; 같은 attainment에 필요한 GPU 수·$·J(Fig 9·10).
- **Q4 메커니즘**: 어디서 시간이 가는가(breakdown), 스트리밍 조기 종료의 time-to-verdict, 창 배칭 효과, 각 구성요소의 누적 기여(Fig 11·12·13).
- **Q5 강건성·격리**: 희석·decoy·fragmented·evasion에서의 recall, 128k flood 아래 다른 tenant의 P99, 인증(Fig 14, Table 6).
